# JavaScript 归属与修改规则

只有用户需求涉及交互时读取本文件。先诊断脚本归属，再决定是否修改。

## 归属分类

- `owned`：选择器只命中目标区域，事件入口和状态都服务该区域，可随目标区域一起修改。
- `shared`：同一脚本或函数同时服务目标区域与其他区域，或由多个区域共同调用。提供必要上下文，但默认不直接修改；需要先缩小作用域或取得用户同意。
- `unknown`：静态分析无法确认归属，例如动态拼接选择器、运行时注入、无稳定锚点或依赖外部脚本。原样保留，不修改。
- `other`：可以确认只属于其他区域。局部编辑时排除。

判断顺序：稳定的区域根节点/唯一自定义 class > `data-type`/`data-section-type` > 事件目标与祖先关系 > 函数调用链 > 泛化标签选择器。`querySelectorAll("ul")` 通常是 `shared` 或 `unknown`；`querySelectorAll('[data-type="banner"]')` 在页面存在多个 banner 时是 `shared`，只有目标区域唯一且调用链不越界时才可判为 `owned`。

## 保留策略

- 先排除能够确认属于其他区域的脚本。
- 当前区域明确拥有的脚本保留并按需求最小修改。
- `shared` 与 `unknown` 原样保留，不得因为“可能相关”而重写。
- 区域片段中缺少脚本时，必须从完整文档取得上下文；不能把脚本复制进 section 造成重复监听。
- 修改选择器时优先限定到目标 section 的稳定自定义 class 或 data 属性。不要用 Tailwind 工具类作 JS 钩子，不新增全局变量、固定 ID 或会跨区域命中的泛化标签选择器。
- 轮播、选项卡、计数器等脚本若通过 `children`、`length`、`querySelectorAll` 动态计算数量，增删项目时默认不改脚本；只同步静态控制项并防止索引越界。
- 表单与站内搜索由系统运行时接管，不新增提交、跳转或搜索 JS。

## 安全边界

禁止引入未知外部脚本、`eval`、字符串事件处理器、危险 URL 协议或绕过系统提交逻辑。现有脚本与本次需求无关时必须保持原样，包括格式和执行位置。
