# 页面修改当前差异 Review

每次生成页面修改草稿后、调用确定性校验前，必须在内部执行一次 Review。Review 不是全页巡检，只判断本次修改是否准确、安全地完成用户最新要求。

## Review 边界

Review 只允许使用以下输入：

- 用户最新一条页面修改要求，以及该要求在当前对话中已确认的必要补充。
- 本次 `target_selector` 和为完成该要求不可缺少的直接依赖。
- 本次采用的 `before_html`、生成的 `after_html` 及两者差异。
- 本次任务按需加载的页面规则模块。
- 服务端返回且能定位到当前目标或本次差异的诊断结果。

以下内容不属于本次 Review，禁止检查、提示、修复或写入摘要：

- 目标区域外未被本次修改触及的 HTML、CSS、JS、组件或页面。
- 其他表单、产品、文章、FAQ、导航、图片、SEO 或 GEO 问题。
- 历史草稿、旧预览、未发布内容、旧诊断和以前对话的待办；本次修改明确以某个未保存预览为基线时，该预览中的既有改动只作为基线保留，不重新 Review。
- 与本次要求无关的响应式、交互、数据结构或内容质量检查。
- 仅因读取完整页面而看到、但未被本次差异触及的既有问题。

不得把“顺便检查”“改进页面质量”或完整页面自查作为扩大 Review 范围的理由。用户要求修改 A 时，只 Review A 及完成 A 所必需的直接依赖，不 Review B。

## Review 项目

按顺序执行，某项与本次修改无关时直接跳过，不得为了执行清单而扩展检查范围：

1. **需求符合性**：本次差异是否准确完成用户最新要求，是否遗漏、误解或增加用户未要求的改动。
2. **范围控制**：变更是否只发生在 `target_selector` 和必要依赖内；目标外内容是否保持原样。
3. **差异最小化**：是否存在无关的格式化、重排、文字改写、属性变更或代码清理。
4. **规则符合性**：只根据本次修改涉及的组件类型加载对应规则，并检查本次新增或改写的结构和属性。
5. **响应式影响**：用户未指定终端时，检查本次差异在手机端和电脑端的结果；用户只指定一端时，只确认另一端未被本次差异影响。
6. **交互与脚本**：仅在本次修改涉及交互或 JS 时，检查脚本归属、作用域和当前交互是否正确，不检查其他脚本。
7. **动态内容所有权**：仅在本次修改涉及动态组件时，检查是否误写运行时数据或破坏当前组件链路。
8. **图片和资源**：仅在本次修改图片或资源时，检查是否使用本次上传回调地址及正确目标，不探测网络可访问性。
9. **HTML 结构**：只检查本次新增或重写的元素，包括混合文本节点规范；不得借此扫描或修复整页旧结构。

## Review 结果处理

- Review 通过后才允许调用确定性校验并创建预览。
- 发现问题时，只修复由本次差异产生或位于当前目标内、且与用户要求直接相关的问题；修复后重新 Review 当前差异。
- 发现目标外问题时忽略并保留原样。若该问题直接阻止服务端完成当前整页校验，只说明阻塞关系，不展开详情、不修复、不加入修改成果。
- Review 无法确认某项是否属于当前目标时，默认不修改；只有缺少用户决定会实质改变结果时才询问用户。
- Review 不能替代服务端确定性校验，也不能绕过版本、结构、安全或系统保护规则。

## 用户可见输出

Review 默认是内部步骤，不显示检查过程、检查清单、技术细节、未修改项或“同时发现”的无关问题。通过后只输出本次实际修改摘要、预览地址和保存/发布状态。

用户明确要求 Review 报告时，也只报告本次要求和本次差异：说明通过项、当前修改内需要处理的问题及结论，不列出目标外既有问题。
