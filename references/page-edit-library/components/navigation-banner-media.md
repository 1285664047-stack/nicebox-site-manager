# 导航、Header、轮播与媒体规则

## 共享 Header、Footer 与导航

- Header/Footer 是站点共享内容，不能作为普通页面 section 保存。修改它们必须明确影响所有页面，并走共享头尾专用读写、预览和回退流程。
- 页面编辑、预览、保存和历史回退时使用当前共享头尾覆盖页面副本；回退页面正文不能回退共享头尾。
- 页面只有一个 `<header>` 和一个 `<footer>`；二者内部及祖先链不嵌套业务 `<section>`。
- PC 导航容器为 `nav[data-type="navs"]`，通常使用 `data-typeid="pc-navs-1"`；移动导航容器为 `#mobile-menu.mobile-menu[data-type="navs"]`，通常使用 `data-typeid="mobile-navs-1"`。保留 `.header-pc-cont`、`.header-mobile-cont` 和 `.max-header-container`；移动端开关通常保留 `.menu-toggle`。
- PC 与移动端各至少保留一个普通状态的 `a[data-type="nav"]` 作为系统克隆模板。导航项保留 `data-type="nav"`、`data-nav-level="1"`、`href` 和 `data-href`；模板可保留唯一 `data-typeid`，但运行时生成的 `pc-nav-*`、`mobile-nav-*` 不能写死。普通模板项不要默认带 `font-bold` 或当前页高亮样式。
- Header 末尾的局部交互脚本应使用 `document.currentScript.closest('header')` 或等价方式取得当前 Header，并在 Header 范围内查询元素。不要把 Header 脚本放入会被重建的导航项，也不要在普通页面正文复制导航监听器。
- Header 相关交互必须跟随共享 Header 保存；不要在普通页面正文复制一份导航监听器。

### 可修改内容与动态所有权

- 可修改并保存到共享 Header：整体布局、背景、边框、阴影、高度、响应式间距；Logo 的尺寸和位置；导航模板项的字体、颜色、间距和 hover class；静态电话、图标、咨询按钮；搜索弹窗外观；汉堡按钮外观和移动菜单动画。
- 可以修改结构或样式但必须保留语义标记：`[data-type="logo"]`、`[data-type="navs"]`、`[data-type="nav"]`、语言切换器、搜索组件及其现有 JS 依赖类名。Logo 图片地址或企业名称优先通过 Logo/企业资料能力修改，直接改 `src` 或文字可能被后续生成覆盖。
- 不得把运行时值当作静态内容修改：导航名称、链接、数量、顺序和层级来自站点页面数据；语言名称和链接来自站点语言配置；二级/三级菜单以及当前页状态由系统重建。需要改变这些业务数据时，改对应页面、排序、层级或语言配置，不硬改 Header HTML。
- 不得写死或依赖运行时标记：`data-page-id`、`data-sub-page-id`、`data-third-page-id`、`pc-nav-*`、动态 `mobile-nav-*`、`#nav-level-2`、`#nav-level-3`、`cur-nav`、`cur-sub-nav`、`cur-third-nav` 以及系统生成的移动端 checkbox id。手写的二/三级菜单外壳会在运行时被删除并重建。
- 语言切换器保留 `data-type="language"`、`data-type="curLanguage"`、`data-type="language-item"`；搜索功能保留 `data-type="searchbox"`、`search-input`、`search-select`、`search-btn`、`data-config` 以及现有弹窗脚本依赖的 class。只修改样式，不伪造动态语言项、搜索配置或结果。
- 前端编辑器禁止直接修改 `[data-type="navs"]` 内 `[data-type="nav"]` 的文字和链接。遇到这类要求时提示：`导航名称、链接、顺序和层级由站点页面数据生成，直接修改 Header 会在预览或发布时被覆盖；请改对应页面或导航配置。`

### 移动端导航定向样式规则

当用户明确要求生成或修改移动端导航，或要求修复移动菜单纵向排列时，只能在当前 Header 的移动导航根容器 `#mobile-menu` 或 `[data-typeid^="mobile-navs-"]` 内操作：

1. 遍历根容器内所有 `a[data-type="nav"]` 和 `.mobile-nav-item`。对每个匹配项的直接父元素追加 `flex flex-col w-full`，只追加缺失 class，不删除或重排原 class。
2. 对每个匹配项自身追加 `block`，只追加缺失 class。`a[data-type="nav"]` 是源模板时，该 class 会传递到系统克隆的一级导航；`.mobile-nav-item` 是运行时多级菜单外壳时，只允许补充该样式，不修改其动态子节点、checkbox、label、链接或 ID。
3. 选择器必须先受移动导航根容器约束，禁止全局修改所有 `[data-type="nav"]` 或 `.mobile-nav-item`。不得改电脑端 `pc-navs-1`、Logo、按钮、搜索、语言、Header 高度、静态 CTA、导航文字、链接、顺序、层级、JS 或任何非移动端导航内容。
4. 修改后确定性校验：移动根容器之外的 HTML 保持不变；每个匹配项直接父元素都包含 `flex flex-col w-full`；每个匹配项自身都包含 `block`；原有 `data-*`、`id`、`href`、`data-href` 和其他 class 完整保留。
5. 如果完整原文中还没有运行时生成的 `.mobile-nav-item`，不得伪造该动态结构；只给移动端 `a[data-type="nav"]` 模板及其直接父元素补 class，并在结果中说明多级外壳将在预览/发布时由系统生成。若运行时再次生成后覆盖手工 class，则应修改导航处理器或其样式规则，不能反复写回渲染结果冒充持久修改。

移动端定向修改前提示：`本次只调整移动端导航的纵向布局 class，不会修改电脑端导航、Logo、按钮、文字、链接、顺序、层级或其他 Header 内容。` 修改后提示：`已为移动端导航项补充 block，并为其直接父容器补充 flex flex-col w-full；其他 Header 内容保持不变。`

## Banner

- 根节点为 `[data-type="banner"]`，单项为顶层 `[data-type="banner-item"]`；字段使用 `title`、`description`、`img`、`link`。
- 图片使用 `<img>`，不得把业务图片只写进 `background-image`。
- 新生成或明确重构的 Banner 必须具有可用轮播行为，不能把多项全部固定叠放或永远停在同一项。默认保留/提供自动播放；用户明确要求手动播放、静态展示或关闭动效时服从用户选择。修改既有 Banner 时保留其原自动播放、暂停和切换方式，不擅自改变速度或触发模式。
- 已有上一张/下一张、分页点、缩略图或 Tab 指示器时，必须保持可点击并切换到对应轮播项；控制项数量、索引和激活状态与真实轮播项一一对应。只有动态生成控制项时才由脚本重建，不在初始 HTML 重复写死。
- 新生成或重构的 Banner 在 HTML 中保留全部真实 `banner-item`，JS 只切换项目的显示、激活、ARIA 或位移状态；不得通过替换一个容器的文字、图片、链接或 `innerHTML` 来伪造多项轮播。
- 增加轮播项时只插入一个相邻结构副本，新项默认非激活；原有项、激活状态、标识和顺序不变。
- 删除后确保剩余第一项及静态控制项成为唯一激活项；只删除对应的静态圆点/Tab/缩略图，动态控制项不手工增删。
- 批量改文案只替换文字节点，保留 `<br>`、图标、图片、链接、class、style、data 属性和交互。
- 轮播数量由脚本动态读取时不修改脚本，也不提前改运行时计数或进度状态。
- 预览时至少核对：自动播放（如启用）、上一张/下一张、每个静态指示器、首尾循环、唯一激活项以及手机端/电脑端切换均正常。任何控制项无响应、索引错位或只能显示第一项时，不得提示修改完成。

## 连续走马灯

连续走马灯是内容持续平移、到边界后无缝衔接的组件，不等同于 Banner、Swiper、产品详情缩略图或带上一张/下一张按钮的逐项轮播。只有页面结构明确包含 `data-marquee-origin` 或 `data-marquee-clone="true"` 时，才按本节处理；普通轮播继续使用 Banner 规则。

### 标准结构与属性

- 标准结构为 `section -> viewport -> track -> 唯一 data-marquee-origin 原始集合 -> 多个真实项目`。viewport 负责裁切可视范围，track 负责平移，原始集合保存真实内容；原始集合至少保留两个直接子项。
- `data-marquee-origin` 标记可保存、可编辑的唯一原始集合，可兼容无值写法和 `data-marquee-origin="true"`。不得给运行时副本、原始集合的子项或多个平行集合重复添加该标记。
- `data-marquee-clone="true"` 只标记脚本运行时生成的副本。副本不属于业务内容，不参与数量、顺序、图片、链接或文本修改，也不得出现在 AI 返回的保存态 HTML 中。
- 创建副本时先移除副本上的 `data-marquee-origin`，再设置 `data-marquee-clone="true"` 和 `aria-hidden="true"`；副本内可聚焦的 `a/button/input/select/textarea` 设置 `tabindex="-1"`，避免屏幕阅读器和键盘重复访问。
- `data-marquee-direction="left|right"` 仅在原组件已经使用时原样保留；当前系统没有统一的速度、暂停或自动播放 data 属性，不得自行虚构 `data-marquee-speed`、`data-marquee-pause` 等协议。
- 原始集合、track 和 viewport 原有的专用 class 属于脚本依赖。修改视觉样式时保留这些 class，只增删与需求直接相关的 Tailwind class。

### 初始化与动画规则

1. 走马灯脚本必须位于对应 `section` 内，通过 `document.currentScript.closest('section')` 或等价的当前脚本父区域取得作用域；所有 DOM 查询限定在当前 section、viewport 或 track 内。
2. 每次初始化、重新计算或响应式尺寸变化前，先删除当前 track 内全部 `[data-marquee-clone="true"]`，并清理上次运行留下的临时位移，再从唯一原始集合重新克隆。不得基于旧副本继续克隆。
3. 初始保存态 HTML 只能包含原始集合，不得写死副本。运行时副本不得写回草稿、预览或正式页面源码。
4. 循环边界必须根据原始集合实际宽度或高度动态计算，并包含实际 gap；不得写死像素边界，也不得用包含副本的 track 总宽度作为边界。
5. 动画优先使用 track 的 `transform: translate3d(...)` 或等价 transform。不得逐帧改写业务节点内容、`innerHTML`、链接或图片。
6. 同一页面的多个走马灯各自维护轨道、边界、方向、暂停状态和计时状态；禁止共享全局变量、固定 ID、全局索引或跨 section 选择器。
7. 内容尺寸、字体、图片或视口尺寸变化可能改变边界。保留原组件已有的 resize/测量机制；修改项目后必须让组件重新初始化或重新加载预览，不能沿用修改前的位移和边界。
8. 原组件有鼠标悬停、键盘焦点、上一张/下一张或计数器行为时，保留其既有交互和无障碍属性；不得为了修改内容擅自改成交互方式不同的另一种轮播。

### 页面修改边界

- 识别到标准单原始集合结构时，只修改 `data-marquee-origin` 的直接子项。允许按用户要求修改原始项目的静态文字、图片、链接和视觉 class，或新增、删除、排序同构项目；不得把脚本生成的副本计入项目数量。
- 新增项目只复制一个原始直接子项的结构，清除编辑器状态和运行态标记，保持项目结构一致；删除后仍须至少保留两个原始项目。修改完成后删除所有运行时副本和 track 上的临时 `transform`，由预览重新生成副本。
- 不得在内容修改中更换 viewport、track、原始集合、script 或特殊 style；不得把走马灯改成网格后仍保留走马灯脚本。走马灯不支持“每行显示 N 个”的网格列数修改，用户要求切换为网格时应作为组件结构转换单独确认。
- 产品、文章等动态数据列表即使视觉上使用走马灯，名称、图片、链接、数量和顺序仍由业务数据生成。页面修改只能调整允许的模板结构与样式，不得把预览数据写死；需要改真实内容时走对应内容管理流程。
- 修改图片时只处理原始项目中的图片；忽略 `data-marquee-clone="true"` 内的重复图片。上传成功后把回调地址写入原始项目，预览时由脚本同步生成副本。
- 修改响应式样式时继续遵守手机端无前缀、电脑端 `md:*` 规则。只改一端时必须保持另一端的原始项目尺寸、间距、裁切、速度感知和交互结果不变。

### 非标准结构与停止条件

- 一个 section 中存在多个 `data-marquee-origin`、原始标记分散在每张卡片、原始集合与副本相互嵌套、初始 HTML 已写死副本，或副本仍带原始标记时，均视为非标准/历史结构。不得猜测集合归属后直接增删项目。
- 非标准结构只做不改变轨道、脚本和标记的局部静态修改；若需求涉及项目数量、顺序、轨道、动画或脚本，停止生成草稿，提示：`当前走马灯使用非标准或历史结构，直接调整项目或动画可能造成重复、跳动或保存运行时副本；需要先规范化走马灯结构。`
- 如果修改结果中仍存在 `data-marquee-clone="true"`、track 保存了运行时 `transform`、原始集合不唯一、项目结构不一致、原始项目少于两个，或脚本作用域超出当前 section，则校验失败并保持原页面不变。
- 不得为了通过校验删除无法理解的脚本、style、方向、暂停或无障碍逻辑，也不得将旧结构自动改造成标准结构，除非用户明确要求“规范化/重构走马灯”并确认影响范围。

标准走马灯项目修改前提示：`本次只修改走马灯的原始内容，运行时复制内容、轨道和动画脚本保持不变；预览会重新生成无缝循环。` 非技术用户的最终结果只说明实际内容变化和预览状态，不主动展示上述属性、选择器或脚本细节。

## 选项卡

- 新生成或明确重构的选项卡必须同时保留全部选项标签和对应内容面板，按稳定 data 属性、自定义 class 或 DOM 顺序建立一一对应关系；不得只保留一个内容容器并在切换时替换其 HTML、文字、图片或链接。
- 同一时刻只允许一个选项和一个内容面板处于激活状态。激活项必须有明确高亮，并同步显示状态、`aria-selected`/`aria-hidden` 等已有无障碍状态；隐藏面板不能继续占据错误布局或接受无意义焦点。
- 切换触发方式优先保留现有组件行为或服从用户明确要求。新建组件未指定时，至少支持点击；如同时支持鼠标经过切换，也必须保留点击和键盘可操作性，不能做成只能 hover 才能访问。
- 增删或排序选项时，标签、内容面板以及一一对应的静态控制项必须同步处理；动态生成的控制项不手工复制。修改后逐项触发检查对应关系和唯一高亮，不能只检查默认第一项。

## Logo、视频和地图

- Logo 的 `data-type="logo"` 放在完整 Logo 单元上；图片加文字时标在共同父节点。更换 Logo 图片必须先上传，不能把临时地址写入页面。
- 视频区域保留 `data-type="video"` 和实际 `<video>`。修改现有视频时不把它替换为图片，也不破坏系统识别的祖先关系。
- 新增视频组件时，实际 `<video>` 必须位于带 `data-type="video"` 的专用祖先容器内，不能裸露在普通区域中，也不能只放封面图片或用普通 `iframe` 冒充视频组件。一个视频组件只绑定一个主要 `<video>`；标题、说明、播放按钮等附属内容沿用模板既有结构，不塞入会被系统当作纯视频节点处理的内部位置。
- 保留 `<video>` 的 `source/src`、`poster`、`controls`、`autoplay`、`muted`、`loop`、`playsinline` 和无障碍属性，只有用户明确要求时才修改。自动播放视频必须同时满足浏览器策略所需的静音等条件；不能承诺浏览器一定允许有声自动播放。
- 视频修改后在手机端和电脑端检查媒体可见、比例正确、控制项可用且不溢出。封面适配遵循媒体语义，不能把所有视频或 Logo 一律强制为 `object-cover`。

### 默认地图：按钮或图片展示并跳转

- 用户只说“增加地图”“显示公司位置”“放一个地图”等，且没有明确要求页面内拖动、缩放、路线或地点搜索时，默认使用普通链接按钮或静态图片链接方案，不加载第三方地图 SDK、`iframe` 或交互插件。
- 先取得准确地址和用户确认的地图详情/导航 URL。用户已明确“按钮、查看地图、打开导航”等按钮语义时使用链接按钮；已明确“地图图片、位置图、地图截图”等图片语义时使用图片。用户没有指定展示形式且两种都合理时，让用户选择按钮或图片，不擅自增加交互地图。
- 按钮方案使用有明确文字的 `<a href="{地图地址}" target="_blank" rel="noopener noreferrer">`，通过 Tailwind class 呈现为按钮；默认文案可按意图使用“查看地图”或“打开导航”。不得使用 `<button onclick>`、`window.open` 或其他 JavaScript 模拟普通链接跳转。
- 图片方案的地图图片必须来自用户提供的地图截图、已有云资源图片或经用户确认的合法静态地图图片；不得用 AI 生成具有虚假道路、地名或坐标的地图冒充真实位置。图片先按上传规则导入云资源库，再把回调 `image_url` 写入 `<img>`，并用同样的 `<a>` 外层链接包裹。
- 图片必须有说明地点的 `alt`；按钮或图片链接都应有明确的可见文案或 `aria-label`。不得把地图详情 URL 写进图片 `src`，不得把地图地址误当作图片地址。
- 默认按钮和静态图片都是普通链接，不伪装成系统交互地图组件；不要为了默认方案擅自添加 `data-type="map"`、`map-container`、地图 SDK 脚本或 API Key。
- 用户没有提供准确地址或地图 URL 时只补问缺失信息，不能猜测坐标、公司位置或导航地址。只有选择图片方案时才要求地图图片；选择按钮方案时不得额外要求用户上传图片。

默认方案提示：`本次可以使用“查看地图/打开导航”按钮，或使用地图图片展示；点击后都会在新窗口打开对应的地图详情或导航地址。这两种方案通常不需要地图 API Key。请确认准确地址、地图链接，并选择按钮或图片形式；选择图片时还需要提供或确认地图图片。`

### 交互式地图插件

- 只有用户明确要求“可直接预览/拖动/缩放的地图插件”“页面内地图”“地图 SDK”等交互能力时，才考虑系统地图组件或第三方地图 SDK。
- 生成代码前必须先说明：交互地图通常需要用户自行申请地图服务 API Key；不同服务商可能按调用量、功能、配额或商业用途收费，免费额度、计费标准和政策可能变化；还可能需要配置允许域名、启用对应 API、完成实名认证或商业授权。
- 必须让用户先选择地图服务商并确认接受其 API Key 与计费要求。未确认服务商、未配置有效 Key 或用户不接受潜在费用时，不生成交互插件，建议改用默认的“地图按钮或图片 + 外链”方案。
- 不得承诺交互地图永久免费，不得虚构公共 Key、把 Key 写入提示词/对话或使用他人的 Key。Key 应通过系统或部署环境的安全配置提供，不写死在页面 HTML、可公开读取的 JS、Skill 或规则库中。
- 使用现有系统地图组件时，根节点保留 `data-type="map"`、唯一 `data-typeid`、地图品牌/地址等配置；显示容器保留 `data-type="map-container"` 和唯一标识，且桌面与移动高度不能为 0。
- 地图脚本属于地图组件并保留在其作用域内；不得在页面修改中暴露、生成或替换服务端密钥。涉及密钥、地图服务、计费或域名白名单配置时停止代码草稿并提示先完成系统配置。

交互方案提示：`页面内可拖动、缩放或搜索的地图需要接入地图服务商插件，通常必须申请 API Key，并可能涉及调用额度、商业授权或按量收费；具体以服务商当前政策为准。请先选择服务商并确认接受相关 Key 和费用要求。若不希望配置，可改用地图按钮或图片加外链方案。`
