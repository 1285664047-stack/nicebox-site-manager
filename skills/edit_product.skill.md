# 修改已有产品

本流程只修改已有产品业务数据，不修改页面模板。通信方式与回退过程保持静默。

## 定位与确认

1. 用户提供编号时精确查询；只提供名称时模糊搜索。存在多条结果时展示编号、名称、语言、分类、价格和状态，让用户选择，禁止自行猜测。
2. 选定产品后读取完整详情，保留返回的一致性摘要供写入使用，不向用户显示该摘要。
3. 支持单独或一次修改多个字段：名称、简介、分类、语言、价格、图片、详情、参数、FAQ、显示状态、排序、SEO 标题、SEO 关键词、SEO 描述、Schema、文件名、详情页和浏览量。
4. `currency` 和 `attachments` 暂不支持修改。请求同时包含支持和不支持字段时，明确说明不支持项，并仅就剩余变更重新展示摘要确认；不得静默丢弃或假报成功。
5. 展示“当前值 -> 新值”的修改摘要，只列本次字段；价格摘要同时显示原货币且明确货币不变。随后优先使用宿主原生结构化提问能力，问题为“请选择下一步操作”，显示三个可点击单选项：`确认保存`、`调整修改内容`、`取消本次修改`。选择“确认保存”后直接保存；选择调整时收集变化并重新展示摘要；选择取消时不写入。宿主不支持原生选项时才使用同样三个文本选项。不得只用“确认保存吗”等开放式问句。参数变化后原确认失效。
6. 文件名变化时只检查当前账号其他产品。存在同名时整次修改不保存；不检查文章和页面。
7. 分类和详情页只能使用查询得到的真实 ID；详情页必须是当前站点同语言的产品详情页。图片先上传，再使用返回地址。

## 保存后的分支

- 服务端只更新用户明确提供的字段。内容被其他操作修改时重新读取、重新展示差异并重新确认，禁止覆盖。
- 修改 `faq_items` 时，服务端自动同步 `schema_json_ld`；FAQ 清空时删除旧 FAQPage，其他 Schema 节点保持不变。
- `content` 或 `parameters` 变化且本次未修改任一 SEO 四项时，保存后询问是否重新生成 SEO。用户确认后完整覆盖 SEO 标题、关键词、描述和 Schema；提示不提 Token 消耗。
- 只有修改前已经存在 FAQ、`content` 或 `parameters` 变化且本次没有修改 FAQ 时，保存后询问是否重新生成 FAQ。原来没有 FAQ 时不询问、不自动生成。
- 保存后读取 `follow_up.choices`，优先通过宿主原生结构化提问显示可点击单选项，不重复输出长篇说明或编号 Markdown。仅 SEO 时显示“更新 SEO / 暂不更新”；仅 FAQ 时显示“更新 FAQ / 暂不更新”；两项都适用时显示“更新 SEO 和 FAQ / 仅更新 SEO / 仅更新 FAQ / 暂不更新”。同时更新时先 FAQ，再使用返回的新一致性摘要生成 SEO。
- `follow_up.choices` 为空时不追加选择问题。原本没有 FAQ 时不得显示 FAQ 选项，也不要额外解释为什么没有该选项。
- 所有重新生成都必须等待用户确认；后台继续记录 Token 消耗和请求来源。

## 显示状态

- 普通产品修改确认不能代替将隐藏产品设为显示的确认。
- 用户要求把 `status` 改为 `1` 时，先保存其他已确认变更并生成该产品预览；展示预览后单独确认，才把产品设为显示。
- 内容显示不等于发布网站，不进入 FTP 流程。

## 用户输出

只报告本次产品实际修改字段和保存结果。需要后续生成时只展示业务选项，不显示内部参数、摘要、接口或执行方式。
